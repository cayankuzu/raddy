# Phase A9: performance and QA. Phase A10: launch package

Read first: `docs/GAME_DESIGN.md` §9, `TEST_PLAN.md`, `ITCH_IO_RELEASE_CHECKLIST.md`, `tools\perf.ps1`, `scripts/core/graphics_quality.gd`.
Findings so far on the dev laptop (i7-13650HX, RTX 5070 Laptop, 1080p): ~50 fps at every quality level; a lower render scale changes nothing; an empty scene floors at ~8.5 ms (hybrid graphics); without scenery 81 fps, without shadows 65; physics ~2 ms, scripts ~1.5 ms; about 750 draw calls, 3 M primitives. So the cost is mostly draw submission and vertex load. Owner: "butter-smooth", min 9.8.

## A9
1. Profile for real: GPU time (`--gpu-profile`), CPU render time, per-pass; find what eats 20 ms beyond the floor. Reduce: shadow casters (only near trees cast; cascades tuned), merge more batches (bigger chunks where range allows), mesh LOD thresholds, impostors or cross-quads for far trees (build in code from the existing tree meshes rendered to texture at import or start, no new downloads), occlusion culling if it helps (terrain and trees block a lot: `OccluderInstance3D` with a cheap generated occluder), visibility ranges, particles, viewport updates (map SubViewport only when open), `_process` work. Quality levels must really differ: Low should run well on integrated graphics (test with `--rendering-driver`/render scale and thinning; estimate from vertex and draw counts since no such GPU is here).
2. Targets on this laptop: at least 75 fps average at 1080p Medium on black_pine with 3 cars and p99 under 20 ms; no hitch when entering a chunk or when a shader first appears: use Godot's pipeline precompilation (ubershaders, `ProjectSettings` rendering/shading options), a loading step that warms up materials, no first-use stutter (measure spikes over 33 ms in a full stage run, target zero after the first 2 s).
3. Load time: a race starts in under 15 s on this laptop (measure; stage build ~3 s; background-thread the build if it blocks the UI, keep the loading screen alive).
4. Memory: measure, target under 4 GB total; textures at 1K-2K; no leaks over a 10-race session (a script).
5. Test matrix script `tools\qa_matrix.ps1`: every stage x every weather x time of day x difficulty builds and validates headless, a bot drives one lap of each stage with zero recoveries, screenshots of each for review. Clean-PC check instructions. Fix what this finds. Known already (A4's final check): the bot (`RouteFollower`) hits a tree on Glacier Ridge in snow about 15 s in and stays braking against it; the flow tests only ever ran in clear weather. The bot must finish every stage in every weather (its corner speeds must know the grip of snow, mud and wet roads), and the flow tests must cover weathers and times of day; if a person would struggle where the bot does, that is a handling or stage finding too.
6. `TEST_PLAN.md` updated with the real numbers and manual checks for the owner.
